# Dotfiles workbench: project-specific context

Evidence: the repository README describes macOS developer tooling, productivity, aesthetics, and developer experience. Existing configuration is primarily terminal/editor tooling, not a committed web design system.

Audience: developer checking a workstation configuration. Primary action for the evaluation fixture: run a safe simulated readiness check and understand any failure. All fixture data must be labelled demo data; never imply it is a real system inspection.

Approved visual references: none supplied or found for this new web surface. Impeccable and Vercel are process references, not approval to imitate their sites. Any user-supplied project reference supersedes these proposals.

Proposed defaults for the fixture only: calm, precise, task-focused light interface; system-ui body text, monospace for technical values; 16px body with 1.5 line-height and 14px minimum secondary text; canvas #f5f7fb, surface #fff, ink #172234, secondary #475569, action #1d4ed8. Verify rendered contrast rather than assuming tokens guarantee it.

Proposed spacing: 4/8/12/16/24/32/48px, content near 1040px maximum, 16-24px mobile gutters. Components: labelled filter/scenario controls, one dominant Run checks action, readable check rows, explicit result/empty/error feedback. Use no decorative imagery unless it explains the task. Preserve focus, disabled/loading feedback and reduced motion.

Do not apply these defaults to other applications. Read their design system and audience first.
