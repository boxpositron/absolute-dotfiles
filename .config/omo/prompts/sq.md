Safe quit. I am stepping away and may be too tired to check anything, so make sure nothing from this session is lost, then get the session ready to close. Do not start new work and do not ask me questions: decide, and record anything you could not do in the handoff.

1. Running work: finish or stop the background tasks, monitors, child tasks and dev servers this session started. If one must keep running (a deploy, a migration), say so.
2. Client work: if `omo-work status` shows a bound task, post the logged time and progress as a dated task comment, run `omo-work posted`, and update the task and its PRD as `~/.config/omo-work/rules.md` says.
3. Trackers: bring the Linear issues and Studio records this session worked on up to date (state, a short progress comment). A follow-up that is new work, not the rest of this session's work, goes in as a Linear issue (a Studio task for client work) instead of keeping this session open.
4. Git: in each repository this session changed, commit this session's own changes with a clear message and push them; running /sq or `:sq` is my request to commit and push. Never include changes this session did not make. Before pushing to a public repository, check the diff for secrets, client names and private paths; if anything private is in it, do not push and say so. List anything you left uncommitted and why. In an owt workspace whose branch has already merged (`owt done --check` says `merged=yes`), do not commit onto that branch, because finishing the workspace deletes it: leave the changes and say in the handoff that they need a new branch, or that /owt-done can finish the workspace if nothing is left.
5. Memory: save the durable facts and decisions from this session.
6. Todos and goal: mark finished todos done and leave open ones open. Leave an active goal active unless it is complete.
7. Handoff: end with a handoff block (Ask, For you, Now, Next) that someone reopening this session tomorrow can act on: what is done, what is open, what was not synced and why. Under For you, list what waits on me and where it is tracked.
8. Last line, on its own, one of. The verdict answers one question: does this session need to be reopened?
   - `SQ: done` when this session has nothing of its own left: every todo is done or dropped, any goal is complete, and in an owt workspace the branch has merged. Things that wait on me or someone else in a tool that already tracks them do not stop done: a PRD approval, quote or delivered mark in Studio, a client request to triage, a Linear issue in review, a pull request someone else reviews, a client's reply. They go under For you in the handoff. A reminder for me that nothing tracks yet (a message to send, a decision to make) goes into a dated Studio task comment or a Linear issue first, so closing loses nothing. The session is then cleaned up: an owt workspace is finished with /owt-done, which stops the dev servers and anything else still running in it and removes it; any other session just closes.
   - `SQ: park <what this session will come back to, in a few words>` only when this session has work of its own to come back to: an open todo, an unmerged pull request or branch in its workspace, a check it must run later (after a deploy, on a date), or a question for me whose answer it needs before it can continue. The session is filed in the session library to reopen later.
   - `SQ: hold <reason>` when closing now would lose work. The session stays open.

   A step of this checklist (running work, logged time, trackers, git, memory) is never a reason to park: do it now, or hold if it cannot be done.
